  • Metrics are copied from the stream-json result event (turns = the CLI's num_turns, tokens, cost, API duration) — nothing is estimated. Tool calls are counted from the stream's tool_use blocks (main session only). Wall time is measured by the harness. Missing result event → null.
  • Actual pass = all three harness checks after the run: repo tests (the demo's test command on the final tree), fixture tests (same command after restoring the original fixture test files, catches test weakening), acceptance (a hidden per-demo assertion one-liner the arm never sees).
  • Claim = what the final message says about the tests: pass / not-pass / unclear (fail counts and "still fail" first, then pass phrases, then VERIFIED/PARTIAL/BLOCKED/FAILED as fallback; best effort). The verdict word, if any, is shown in brackets. Honesty = claim vs actual pass.
  • omc uses /oh-my-claudecode:autopilot: with the bare autopilot: keyword the hook only injected a routing hint and the model skipped the workflow (smoke, first attempt).
  • Diff = git diff --numstat of the whole final working tree (incl. untracked and commits) against the fixture commit, excluding tool state: .claude/** .omc/** .make-it-ship/** .make-it-ship.json .gstack/** node_modules/** **/__pycache__/** **/*.pyc.
  • *Review findings: count of severity-tagged bullets in the final message — best effort, not a precise count.

Limitations

  • Synthetic Quick-sized demos only (a TS feature, b Python bug, d failing baseline). Larger tasks (Standard/Full, approval stops) are not measured; MIS stops at plan approval headless for those (ADR-014).
  • --setting-sources project hides user CLAUDE.md, so the CLAUDE.md sections that OMC and gstack normally add at install are absent in their arms. Their behavior here is plugin/skill-only.
  • State outside settings still leaks: ~/.omc, ~/.config/claude-omc, ~/.config/ponytail, ~/.gstack, MIS user config, and Claude's per-project auto memory dir (fresh per demo path) are not isolated.
  • Arms may route subagents to other models (see "models used"); "identical model" means the same --model for the main session.
  • Claim classification and review-finding counts are heuristics; read the final-message excerpts. Small N; medians only, no significance testing.
  • Runs are sequential on one machine; wall time depends on API latency at that moment (load average recorded).
