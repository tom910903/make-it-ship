# ADR-0003: 단일 플러그인으로 원본 4종 전체 대체 (M6~M10)

- 일시: 2026-10-20
- 상태: 채택
- 결정자: 사용자
- 관련: Spec ADR-010(개발 관련 기능 흡수), Spec §14.4(제외), ADR-003(런타임 의존성 0), PRD 11.2(MVP에서 하지 않을 것)

## 맥락
M1~M5는 원본 플러그인 OMC·Superpowers·Ponytail·gstack의 **개발 워크플로 기능**만 `/make-it-ship:run` 단계로 재구성해 흡수했다. 사용자는 Make It Ship **하나만 설치해** 원본 4종의 기능을 모두 쓰기를 원한다. 현재 구현과 그 목표 사이에는 다음 차이가 있다.

1. **항상 켜진 동작이 없다.** 원본은 모든 대화에 적용된다. Make It Ship은 run 안에서만 동작한다. 해당 동작은 다음과 같다.
   - 세션 시작 시 스킬 사용 규율 주입
   - Ponytail 스타일 레벨
   - 키워드 트리거(ralph, ulw 등)
2. **원본의 도구가 없다.** 다음 도구가 빠져 있다.
   - OMC MCP 도구: LSP, ast-grep, python_repl, notepad, memory, state 등
   - tmux 팀 작업자
   - gstack 브라우저 데몬
3. **Spec §14.4에서 제외한 기능이 있다.** 설정·doctor·skill 관리, 연구·자가 개선 루프, 배포 후 운영, PDF 변환, 브라우저 자격증명 도구 등이다.

## 결정 (2026-10-20 사용자 응답)

**범위**
- 위 세 가지를 모두 구현한다.
- 단, 다음 두 가지는 **제외**한다.
  - **BSP:** 사용자 결정으로 M5-05를 제거했다.
  - **알림:** OMC configure-notifications. 외부 클라우드 전송이고 사내 정책 문제가 있다.

**의존성**
- **npm 의존성을 허용한다.** ADR-003(런타임 의존성 0)을 이 범위에 한해 대체한다.
- 의존성을 추가할 때마다 PROGRESS에 사유를 적는다.
- 설치는 guard의 ask를 거친다.
- 기존 M1~M5 코어(`mis`, guard)는 계속 무의존으로 유지한다.

**자격증명을 다루는 기능**
- setup-browser-cookies, connect-chrome, scrape는 포함한다.
- 다음 접근은 매번 guard가 ask한다.
  - 쿠키·세션 접근
  - 실제 Chrome 연결
  - 외부 사이트 요청

**설치 형태**
- **단독 설치**를 전제로 한다. 다른 플러그인이 없어도 모든 기능이 동작해야 한다.
- 원본과 함께 켰을 때의 공존은 목표가 아니다.

**비교와 보고서(M10)**
- 원본 4종과 Make It Ship을 같은 합성 데모로 **실제 실행해** 비교한다.
- 결과는 **로컬 HTML 보고서**로 만든다. 외부 업로드는 하지 않는다.

## 대체되는 이전 결정
- **Spec §14.4 제외 표:** 알림과 BSP를 뺀 나머지 행이 구현 대상이 된다. Spec 본문은 수정하지 않고 PROGRESS `SPEC_CHANGES`에 기록한다.
- **PRD 11.2 "자동 프로세스 자가 수정":**
  - self-improve를 구현한다.
  - 단, 프로세스·스킬 변경은 항상 사용자 승인 후 적용한다(learn과 같은 규칙).
  - 기획서는 수정하지 않는다.
- **ADR-003 런타임 의존성 0:** 위 "의존성" 항목대로 바뀐다.

## 유지되는 원칙
- 증거 없이 완료라고 하지 않는다(`mis check`/`mis verdict`).
- 위험 작업은 ask한다.
- 테스트 약화를 금지한다.
- 사내 코드·데이터를 테스트에 사용하지 않는다.
- 외부 모델 CLI 호출은 ask한다.
- guard는 fail-closed다. 반면 **새로 추가하는 항상 켜진 훅**(SessionStart, UserPromptSubmit 등)은 **fail-open**이다. 오류가 나도 세션을 막지 않는다.

## 범위 기준
- 구현 대상은 `docs/research/gap-matrix.md`의 MISSING/PARTIAL 행이다.
- 표에 없는 기능은 PROGRESS 제안으로만 기록한다.

## 실측 (2026-10-20, Claude Code 2.1.292)
플러그인에 포함된 `.mcp.json` MCP 서버를 시험했다. 시험용 서버는 `probe_ping` 도구 하나를 가진 플러그인이다.
- `--strict-mcp-config`를 켜면 **로드되지 않는다**. 모델 응답은 `NO_TOOL`이었다.
- 플래그를 빼면 로드되어 호출된다. 응답은 `PONG-7731`이었다.

따라서 M7 이후 MCP 도구의 E2E는 `--strict-mcp-config` 없이 실행해야 한다. 이때 사용자 MCP 설정이 섞이므로 그 영향을 보고서에 적는다. 다른 방법은 `--strict-mcp-config --mcp-config <플러그인 서버 설정>`으로 플러그인 서버만 명시하는 것이다. 이렇게 하지 않으면 도구 계층 검증이 조용히 빠진다.
